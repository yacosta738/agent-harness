# Multi-Runtime Distribution — Architecture Decision

## Context

Agent Harness was designed for OpenCode, with all distribution logic tied to `~/.config/opencode`.
To support Claude Code, JetBrains Junie, and Antigravity CLI, we need a distribution layer that
preserves a single canonical source for shared skills, instructions, and workflow contracts while
producing native layouts for each runtime.

## Decision

Extend the existing bundle generator (`scripts/generate-bundle.mjs`) to support multiple targets via
adapter definitions, rather than introducing a parallel distribution framework.

## Rationale

1. **Single source of truth** — Skills, prompts, and commands live in one place (`skills/`,
   `prompts/`, `commands/`). Adapters define how each runtime discovers and loads them.
2. **Minimal transformation** — Each adapter declares which files to include and how to map them.
   The generator handles the rest: path resolution, reference validation, and target-specific file
   generation.
3. **Backward compatibility** — The OpenCode adapter preserves the existing behavior exactly. No
   changes to the OpenCode output.
4. **Deterministic output** — Sorted files, no timestamps, reproducible builds. The same input
   always produces the same output.
5. **No duplicated source trees** — Generated bundles are artifacts, not maintained code. A change
   to a skill is made once in the canonical repo and distributed to all targets.

## Adapter Boundaries

Each adapter defines:

- **`name`** — target identifier (opencode, claude-code, junie, antigravity).
- **`defaultTarget`** — where the bundle is installed (e.g., `.claude`, `.junie`, `.agents`).
- **`components`** — which repo paths to include, grouped by logical component (core, skills, sdd,
  etc.).
- **Target-specific files** — generated by the bundle generator (e.g., `CLAUDE.md`, `AGENTS.md`).

## Source of Truth

| Content            | Location                          | Owned by         |
|--------------------|-----------------------------------|------------------|
| Skills             | `skills/**/SKILL.md`              | Canonical repo   |
| Commands           | `commands/*.md`                   | Canonical repo   |
| Prompts            | `prompts/**`                      | Canonical repo   |
| OpenCode config    | `adapters/opencode/opencode.json` | OpenCode adapter |
| Claude Code layout | Generated                         | Bundle generator |
| Junie layout       | Generated                         | Bundle generator |
| Antigravity layout | Generated                         | Bundle generator |

## Target-Specific Transformations

### Claude Code

- Skills land in `.claude/skills/` for native discovery.
- `CLAUDE.md` is composed from orchestrator, writing style, and communication prompts.
- No agent registration JSON — Claude Code discovers agents from skill descriptions.
- Partial permission translation — Claude Code has a native permission system in
  `.claude/settings.json` using `allow`, `ask`, and `deny` arrays (e.g., `Bash(git push *)`,
  `Read(**/.env)`). OpenCode's granular task permissions (subagent delegation) are not translated.
  Bash and read permissions are mapped to Claude Code's format.

### Junie

- Skills land in `.junie/skills/` for native discovery.
- `.junie/AGENTS.md` is composed from orchestrator, writing style, and communication prompts.
- Subagents use YAML frontmatter with `name`, `description`, and `tools` groups.
- Partial permission support via tool groups.

### Antigravity CLI

- Root `AGENTS.md` is composed from the orchestrator, writing style, and communication prompts.
- Skills land in `.agents/skills/` and command instructions are converted into discoverable skills.
- Custom agents use `.agents/agents/<name>/agent.md` with Antigravity `name`, `description`, and
  `subagent: true` frontmatter; nested OpenCode prompt frontmatter is removed during generation.
- `.agents/mcp_config.json` is generated with an empty `mcpServers` object; users configure their
  own machine-specific servers.
- OpenCode permission rules and provider configuration are not translated; global `~/.gemini/`
  files are not modified.

## Consequences

**Positive:**

- One change to a skill propagates to all runtimes.
- Each runtime gets its native layout without manual maintenance.
- Cross-target validation catches leaks of runtime-specific references.
- Existing OpenCode users are unaffected.

**Negative:**

- Runtime-specific features (permissions, `{file:...}`) require adaptation or are documented as
  unsupported.
- The bundle generator must be updated when a runtime changes its discovery conventions.
- Generated `CLAUDE.md` and `AGENTS.md` are large files composed from multiple prompts.

## Verification

- `npm run deploy:all` renders all four targets.
- `node scripts/validate-targets.mjs` validates all bundles with zero failures.
- OpenCode bundle passes existing `check-refs.mjs` validation.
- No OpenCode-specific paths leak into Claude Code, Junie, or Antigravity bundles.
